# WP05 — Draft tooling: section lint and build script

## What changed

- `tools/check_section.py`: a standalone CLI, `check_section.py FILE [--must TEXT]...`,
  that lints one draft section file deterministically. It is import-friendly
  (each rule is its own function, `check_file()` composes them, `main()` is
  the CLI entry point) so the unit tests exercise the rules directly rather
  than only through subprocess exit codes.
  - `check_nonempty`: fails only on a literal empty string.
  - `check_must`: fails once per missing `--must` string, case-sensitive
    substring match.
  - `check_unresolved_markers`: regex `\b(TBD|TODO|FIXME|XXX)\b`, matched
    case-sensitively (lowercase `tbd`/`todo` do not trigger it) and as whole
    words only (`ATBDX`, `TODOIST` do not trigger it); reports each distinct
    marker word found once, not once per occurrence.
  - `check_throughput_claims`: splits the file into sentences (naive
    `.`/`!`/`?`-terminated runs over whitespace-normalized text) and flags
    any sentence containing `"Gbps"`, `"Mpps"`, or `"line rate achieved"`
    unless that same sentence also contains `"pending measurement"` — the
    spec's "outside a sentence containing ..." is read as *within the same
    sentence*, not merely somewhere in the file.
  - `check_balanced_fences`: counts lines whose stripped content starts with
    `` ``` ``; fails if that count is odd (an unterminated fence).
  - `check_first_line_heading`: fails if the first non-blank line does not
    start with `#`, or if there is no non-blank line at all.
  - `check_file` reports "file does not exist" and stops (no content to
    check further); otherwise it runs every other check against the file's
    text and returns the full list of failures, so multiple independent
    problems each get their own line, matching "print one line per failure."
  - `main()` returns 0 only if `check_file()` found nothing; otherwise it
    prints each failure line and returns 1.
- `draft/build.sh`: `set -euo pipefail`; `cd`'s to its own directory so it
  always runs "from draft/" regardless of caller's cwd; creates `out/`;
  runs `kramdown-rfc draft-vladyka-schc-vxlan-fragmentation-00.md > out/<name>.xml`
  then `xml2rfc --text --html out/<name>.xml`. Not executed in tests (the
  main draft file does not exist yet, per the package note) — verified with
  `bash -n` only, as instructed.
- `tests/test_check_section.py`: imports `tools/check_section.py` directly
  (inserts `tools/` onto `sys.path`, mirroring how `tests/test_examples.py`
  imports `tools/gen_examples.py`). Covers each rule with at least one
  passing and one failing case, plus:
  - whole-word/case-sensitivity edge cases for the marker check,
  - the "claim word and `pending measurement` must share a sentence" rule
    (a file with both in *different* sentences still fails),
  - `check_file` aggregating multiple independent failures from one bad
    file, and missing-file handling,
  - `main()`'s exit code and printed output for both a passing and a
    failing file.

printed nothing and exited 0.

## Non-obvious choices

- **Marker check reports each distinct word once, not once per occurrence.**
  The spec says "print one line per failure"; a section accidentally full of
  five `TODO`s would otherwise flood the output. One line per *kind* of
  unresolved marker found seemed like the useful granularity — the message
  doesn't claim a line number anyway, so repeating it per occurrence
  wouldn't add information.
- **"outside a sentence containing 'pending measurement'" is scoped to the
  sentence, not the file.** A file that mentions a `Gbps` number in one
  sentence and separately says "results are pending measurement" in another
  sentence still fails — tested explicitly
  (`test_throughput_claims_pending_measurement_must_share_sentence`). This
  reading matches the hard invariant that the draft "never claims
  throughput": a stray disclaimer elsewhere in the document shouldn't
  launder an unqualified claim.
- **Fence balance is checked by counting `` ``` `` lines, not by tracking
  open/close state or language tags.** kramdown-rfc markdown only needs
  "every fence that opens, closes"; counting is sufficient and simpler than
  parsing fence language annotations, and false positives would require a
  literal triple-backtick appearing an odd number of times outside of fence
  syntax, which doesn't occur in this project's prose.
- **`check_file`'s only short-circuit is a missing file.** An empty file
  still runs every other check against empty text, so it correctly reports
  *both* "file is empty" and "first non-blank line does not start with '#'"
  (there being no non-blank line) rather than hiding the second behind the
  first — each independent problem gets its own line as the spec asks.
- **`draft/build.sh` resolves its own directory via `BASH_SOURCE[0]`** so
  `bash draft/build.sh` works the same whether invoked from the repo root or
  from inside `draft/`, while still satisfying "from draft/, run
  kramdown-rfc ...".

## Known limitations

- The sentence splitter in `check_throughput_claims` is intentionally naive
  (split on `.`/`!`/`?`, not abbreviation-aware). It is adequate for this
  project's plain prose; it would misparse something like "e.g. 10 Gbps" as
  two sentences, which only matters once such text appears in a real
  section (none currently do).
- `draft/build.sh` is unexecuted beyond `bash -n`, per the package
  instruction, because `draft/draft-vladyka-schc-vxlan-fragmentation-00.md`
  does not exist in this worktree yet.

## Question

None — the deliverable's wording left two small interpretive choices
(reporting granularity for repeated markers; whether "pending measurement"
must share a sentence with the claim word), both resolved above in favor of
the stricter/more useful reading and covered by tests, so there was no
blocking ambiguity.
