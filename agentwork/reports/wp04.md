# WP04 — Worked examples from the reference model

## What changed

- `tools/gen_examples.py`: computes and renders the two examples required by
  DESIGN.md "Items to settle" #5, using the WP02 sender (`fragment_frame`)
  and WP03 receiver (`Receiver`) directly — nothing is hand-computed.
  - **Example A** (last-fragment-first completion): a deterministic
    1514-byte illustrative Ethernet frame (`byte[i] = i mod 256`) is
    fragmented for PMTU 1500 / IPv4 (`H_IP=20`), producing the pinned
    1454/60-byte slices and 1496/106-byte outer IP lengths from DESIGN.md.
    The final fragment (index 1, carrying the RCS) is fed to the receiver
    first, then the nonfinal fragment, on a fixed fake clock (t=0.0 ms,
    t=1.0 ms). The script asserts `PENDING` then `DELIVERED`, shows the
    2-bit bitmap after each datagram, and prints the final CRC-32C.
  - **Example B** (deadline expiry): the same frame; only the final
    fragment arrives (t=0.0 ms), opening the entry with
    `expiry = first_rx + Δ = 5.0 ms`. The missing nonfinal fragment then
    arrives at t=7.0 ms (after expiry, with no `sweep()` call in between).
    The script asserts the receiver retires the entry as expired on that
    arrival and counts the arriving fragment as `late` — demonstrating the
    hard invariant "expired entries are ineligible even before a sweep"
    without ever calling `sweep()`.
  - Header fields (RuleID, VNI, Frame ID, Index, Count) are rendered as
    separate hex fields rather than one opaque blob, per the deliverable's
    "show header fields in hex".
  - `main()` prints the rendered Markdown and writes it to
    `draft/generated/examples.md`.
- `tests/test_examples.py`: imports `tools/gen_examples.py` as a module and
  checks:
  - regenerating (`render(build_example_a(), build_example_b())`) matches
    the committed `draft/generated/examples.md` byte for byte;
  - the committed file ends with a newline and has no tab characters;
  - the pinned slice lengths (1454/60) and outer IP lengths (1496/106) for
    Example A;
  - Example A's event sequence (`PENDING` → `DELIVERED`, bitmap `01` → `11`)
    and its counters (`completed=1`, `expired=0`, `late=0`);
  - Example A's delivered RCS equals `crc32c` of the illustrative frame;
  - Example B's event sequence (`PENDING` → `LATE`) and counters
    (`completed=0`, `expired=1`, `late=1`);
  - Example B's `expiry_ms` equals the configured Δ.
- `draft/generated/examples.md`: committed output of the generator (the
  `draft/` and `draft/generated/` directories did not exist before this
  package; they are created here as a side effect of owning this one file —
  WP05/WP12 own the rest of `draft/`).

## Non-obvious choices

- **Illustrative parameters are fixed constants, not derived from any
  existing test.** VNI `0x003039` (12345), Frame ID `1`, peer name
  `"vtep-2"`, Δ=5.0 ms, L=50.0 ms are arbitrary but deterministic; DESIGN.md
  does not pin these values (only the 1514-byte-frame/PMTU-1500 slice and
  outer-IP-length numbers are pinned, and those are asserted against
  `sender.py`'s output rather than hand-copied).
- **Example B needs no explicit `sweep()` call.** `Receiver.receive()`
  lazily retires an expired entry when a new fragment for that key arrives
  after `expiry`, per DESIGN.md §Receiver algorithm step 2 ("a fragment
  that finds such an entry retires it as expired, counted once, and is
  itself counted as late"). Driving the example this way — rather than
  calling `sweep()` first — demonstrates the "expired entries are
  ineligible even before a sweep" hard invariant directly in the worked
  example instead of just asserting it.
- **Header fields shown per-field, not as one hex blob.** The deliverable
  asks to "show header fields in hex"; rather than dumping the raw 14-byte
  header as one hex string, `_header_fields_hex()` renders each of
  RuleID/VNI/FrameID/Index/Count as its own `name=0x...` token in one
  column, so the reader sees labeled hex per field without needing a wider
  table.
- **Time unit is milliseconds, stated explicitly.** `ReceiverConfig`/the
  clock are unit-agnostic floats in the reference model; the example picks
  "ms" as a concrete, readable unit for Δ=5.0 and the event timestamps and
  says so in the "Common parameters" section, consistent with DESIGN.md
  treating Δ as a configured deadline budget without mandating a unit.
- `draft/` and `draft/generated/` did not exist in this worktree before
  this package ran (WP05, which creates `draft/build.sh`, has not landed
  yet in this history). Only `draft/generated/examples.md` is created/owned
  here, matching the package's `owns:` list; no other file under `draft/`
  was touched.

## Known limitations

- The worked examples use an illustrative frame and parameters chosen for
  this package, not values mandated elsewhere in DESIGN.md beyond the
  pinned 1514/1500/1454/60/1496/106 numbers, which are asserted (not just
  asserted-equal to a hardcoded literal — they come from calling
  `fragment_frame` itself, so they track the sender implementation).
- Markdown table cells containing the pipe-adjacent em dash `—` for "no RCS
  on a nonfinal fragment" are plain Unicode characters, not escaped; this
  matches how `draft/generated/` Markdown is expected to be consumed
  (kramdown-rfc / direct inclusion), per the draft tooling conventions
  described in `agentwork/packages/WP05-draft-tooling.md`.

## Question

None — WP02 and WP03 (sender/receiver) were present and stable, and
DESIGN.md's "Items to settle" #5 explicitly asks for these two example
types without constraining the illustrative frame/VNI/Frame ID/peer/Δ/L
values, so no blocking ambiguity was hit.
